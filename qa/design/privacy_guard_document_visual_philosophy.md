# Privacy Guard Document Visual Philosophy

## Guarded Document

The privacy screen should feel like a secure document chamber inside the V Slot cabinet, not a blank web panel with an error pasted on top. The visual system is quiet protection: dark glass, sealed rails, violet document depth, cyan verification lines, and restrained gold lock accents.

`privacy_web_panel_premium.webp` and `privacy_web_panel_landscape_premium.webp` replace the old flat document placeholder. The WebView itself is the only source of real policy content; the panel must not contain fake policy text, fake URLs, or simulated paragraphs. It exists as a protected legal frame around the live WebView and the image-based error state.

The error state needs to communicate trust before it communicates failure. Badge, message, and retry action should sit inside a single image-only security field, with the center kept clean for the Russian bitmap label. The work should look meticulously crafted, like a master interface artist tuned every line to make legal readiness feel deliberate.

The image must avoid fake policy text, fake URLs, and anything that suggests external casino navigation. It should strengthen store-readiness through material and composition only. Rows and locks can imply a protected document, but all readable information remains in the existing approved image labels and accessibility strings.

Motion is a short seal pulse when an error appears: the document chamber wakes up, highlights the guard badge, then settles. The result should feel stable, careful, and compliant, with no ongoing attention-grabbing loop.
